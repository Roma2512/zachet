# Пошаговая инструкция проверки

## Сценарий 1. Первый запуск (пустой HKCU)
1. `dotnet run`
2. Enter на запрос каталога-источника — создастся `demo-source` с 5 файлами.
3. Enter на запрос каталога-назначения — `demo-backup`.
4. Ожидаемый вывод:
   - результат `cmd /c ver` (или `uname -a`);
   - последовательное копирование (строки `[Seq] OK ...`);
   - pipeline (строки `[Pipe] OK ...`);
   - путь к `demo-backup/backup-log.json`.
5. Открыть `backup-log.json` — массив записей с полями `sourceHash`/`destinationHash`, `success: true`.

## Сценарий 2. Второй запуск (каталог из HKCU)
1. Снова `dotnet run`.
2. Появится «Сохранённый ранее каталог: ...» и вопрос «Использовать его? (Y/n)».
3. Нажать Enter (Y). Источник — Enter (тот же `demo-source`).
4. Вывод аналогичен Сценарию 1, в `HKCU\Software\Variant05\BackupManager\DestinationDirectory` сохранён путь.

## Сценарий 3. Проверка SHA256 при повреждении файла
1. Запустить `dotnet run`, дождаться копирования.
2. Открыть `demo-backup/pipeline/file3.txt`, изменить один символ.
3. Запустить ещё раз.
4. Для `file3.txt` в логе появится `success: false`, `error: "Хеши не совпадают при контрольной проверке"`.

## Сценарий 4. Пустой каталог-источник
1. Создать пустую папку `empty`.
2. `dotnet run`, в качестве источника указать путь к `empty`.
3. Ожидаемый вывод: `[Discovery] Найдено файлов: 0`, затем `[Discovery] Копировать нечего.`

## Сценарий 5. Отмена через Ctrl+C
1. Во время копирования нажать Ctrl+C.
2. Процесс завершается через `CancellationToken` (исключения отмены не маскируются).
